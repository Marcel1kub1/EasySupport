# Release notes

The dashboard checks the public GitHub Releases API when a guild dashboard or release-notes page is opened. Results are cached for five minutes and link to the original release. If GitHub is temporarily unavailable, the dashboard logs the fetch error and uses the last locally generated feed when available.

## Release process

Every pull request targeting `main` must:

<Callout type="note">
  **Release policy** — Bump the version in `package.json`, add the same version to `src/data/releases.json` and `src/data/releases.md`, and pass the repository release policy.
</Callout>

1. Bump the version in `package.json`
2. Add the same version to `src/data/releases.json` and `src/data/releases.md`
3. Pass the repository release policy

After the change is merged, GitHub automatically creates the matching `v<version>` release, which is then available to the dashboard release feed.

## Generating release notes locally

Maintainers can generate factual draft notes locally from Git history; the generator does not send code to an AI service. It groups commit subjects using [`scripts/release-notes.rules.json`](./scripts/release-notes.rules.json), lists changed paths, and includes slash-command definitions when command files change:

```bash
npm run release:notes -- --from v2.3.0 --version 2.4.0
```

Review `src/data/releases.json` and `src/data/releases.md` before publishing if you want local notes to serve as a fallback. An offline instance cannot display new releases while it is offline.

Read and dismiss state is stored in the browser; no Discord message is sent.
